## O que construir

Entregar o primeiro `OkfChangeSet` durável por API e UI contra SQLite, usando o mesmo contrato de repositório previsto para PostgreSQL. Criação idempotente, leitura e edição por nova revisão aplicam isolamento tenant-área, `If-Match`, hashes canônicos e regras no domínio, não no adapter.

## Stack e geração de código

- Skill: `novo-modulo` — usar apenas se a responsabilidade não couber nos módulos `okf` e de orquestração existentes; atualizar integralmente os contratos ADR-017.
- Skill: `rnf-validation` — aplicar conceitos de schema e erro, sem importar RNF Node.
- Frontend: tracer de criação, consulta e edição do ChangeSet com o Assured UI.
- Justificativa RNF: persistência é Python/SQLite e Python/PostgreSQL; não existe gerador RNF compatível neste projeto.

## Critérios de aceite (verificáveis)

- [x] `POST/GET/PATCH /authoring/changesets` preserva estado após reinício e executa replay por `Idempotency-Key` sem duplicar agregado.
- [x] Edição com `If-Match` obsoleto retorna `412` e não sobrescreve revisão concorrente.
- [x] As mesmas provas contratuais rodam contra adapters SQLite e PostgreSQL substituíveis, sem regra de domínio no adapter.
- [x] Leitura e escrita cruzadas entre tenant ou área falham fechadas.
- [x] Banco, fixtures e respostas não contêm token, segredo ou credencial delegada.
