## O que construir

Entregar seleção e administração de área tenant-local ponta a ponta. O servidor deriva o tenant do `tid` validado, resolve áreas pelos object IDs de grupos Entra e calcula permissão efetiva por App Role interseccionada com área; `X-Area-ID` seleciona contexto, mas nunca concede autoridade.

## Stack e geração de código

- Skill: `rnf-validation` — aplicar o baseline de validação e erros aos contratos HTTP, sem biblioteca RNF Node.
- Skill: `cura-design` — seletor global e administração responsiva em componentes CURA.
- Justificativa RNF: o backend obrigatório deste repositório é Python/FastAPI; o CLI RNF Node é incompatível. Alterar módulos existentes manualmente conforme ADR-017.

## Critérios de aceite (verificáveis)

- [ ] `GET /me` retorna somente áreas autorizadas para o `tid`, grupos e App Roles validados.
- [ ] `GET/POST/PATCH /tenant/areas` aplica papel Admin, `If-Match`, validação e isolamento tenant-local.
- [ ] Reader, Author, Approver e Admin obedecem à matriz; Admin não herda Approver.
- [ ] Testes negativos cobrem tenant A/área A, tenant A/área B e tenant B.
- [ ] O seletor CURA não exibe nem aceita como válida uma área fora do contexto resolvido pelo servidor.
