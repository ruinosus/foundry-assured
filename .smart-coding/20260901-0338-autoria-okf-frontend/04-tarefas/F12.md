## O que construir

Entregar publicação Azure DevOps pela mesma porta de domínio, usando OBO e REST API 7.1 com escopo mínimo `vso.code_write`. O adapter traduz branch, commit, PR e consulta de merge para estados comuns sem esconder conflitos ou semântica própria do provedor.

## Stack e geração de código

- Skill: `sdk-verify` — confirmar contratos Entra OBO e Azure DevOps REST 7.1 em fontes oficiais.
- Skill: `novo-modulo` — aplicar ADR-017 caso o adapter exija módulo novo.
- Skill: `rnf-validation` — validar entrada e erros no FastAPI Python, sem RNF Node.
- Frontend: jornada de publicação e consentimento no Assured UI, coerente com GitHub.
- Justificativa RNF: o backend é Python; não há comando RNF aplicável.

## Critérios de aceite (verificáveis)

- [ ] OBO solicita somente `vso.code_write` e usa a identidade do Approver autorizado.
- [ ] Branch, commit e PR correspondem ao conjunto aprovado e não duplicam no replay idempotente.
- [ ] Conflito de ref, 4xx não transitório e decisão humana não recebem retry automático.
- [ ] Erros comuns preservam semântica comparável aos do GitHub sem apagar detalhes operacionais necessários.
- [ ] Smoke autenticado prova branch, PR, consulta e replay em projeto Azure DevOps aprovado.
