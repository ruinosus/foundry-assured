## O que construir

Entregar o ciclo completo de um endpoint direto: proposta inerte, decisão Admin auditável e primeira
discovery somente depois da validação de egress. URL/auth são imutáveis e qualquer redirect é
recusado. Um lease limita discovery concorrente por tenant+source.

## Stack e geração de código

Backend Python existente. RNF/CLI não se aplica; a mudança pertence ao módulo Python
`platform_ops` e às superfícies existentes de tenancy/audit, sem criação de módulo ou CRUD RNF.

## Critérios de aceite

- [x] Criar endpoint `pending` não resolve DNS nem realiza request; alterar origem/auth exige novo id.
- [x] Somente Admin aprova/rejeita, com motivo e evento distinto de snapshot/tool approval.
- [x] Apenas HTTPS/443, host DNS e origem exata; IP literal, userinfo, fragmento e redirects falham.
- [x] Todos os A/AAAA são validados antes de cada conexão e classes privadas/metadata são negadas.
- [x] Lease de 30 s permite uma discovery por tenant+source e concorrente recebe `429 MCP_DISCOVERY_BUSY`.
- [x] Testes cobrem IPv4/IPv6, DNS rebinding, redirect e dois tenants com ids/hosts iguais.
