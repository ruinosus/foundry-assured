## O que construir

Fechar o caminho negativo ponta a ponta contra servidores lentos, infinitos, profundos ou
maliciosos. Cada violação retorna um erro estável, não cria snapshot parcial, preserva contexto
stale quando aplicável e emite somente sinais agregados sem conteúdo.

## Stack e geração de código

Backend Python existente. RNF/CLI não se aplica; são limites e observabilidade das integrações
Python já criadas. Reutilizar telemetria e handlers públicos do repositório.

## Critérios de aceite

- [x] Timeouts 5/10/15 s são aplicados e mapeados para `MCP_DISCOVERY_TIMEOUT` retryable.
- [x] Limites 200 tools, 256 KiB, 32 KiB/schema, depth 12, 200 properties, name 128 e description 2048 são testados nas bordas.
- [x] Cursor repetido, paginação sem progresso, tool duplicada e schema inválido falham sem snapshot parcial.
- [x] Envelope HTTP implementa todos os códigos do detalhamento com correlationId e sem stack/payload.
- [x] Logs/spans/métricas contêm somente ids/hashes pseudonimizados, duração, outcome, contagens e code.
- [x] Canary em descrição/schema/error não aparece em resposta, log, trace, Table, Blob ou audit.

## Checklist NORDOR-122

- [x] Toda entrada remota é limitada antes da materialização/persistência.
- [x] Concorrência, tempo, bytes, paginação e profundidade possuem teto verificável.
- [x] Erro inesperado é genérico para cliente e detalhado só no canal protegido.
- [x] Logs/traces não carregam URL, query, schema, descrição, token ou PII.
- [x] Testes maliciosos comuns e threat model estão ligados aos gates de CI.

## Decisões / notas

- O `MCPStreamableHTTPTool` continua responsável por transporte, sessão e paginação; o proxy de
	sessão acrescenta apenas os limites de assurance ausentes no SDK instalado.
- Violações de limite e protocolo invalidam a discovery inteira antes de qualquer evidência.
- Erros HTTP e telemetria usam conjuntos allowlisted; conteúdo remoto nunca compõe esses sinais.
