o que faz

Pergunte → fundamente → resolva → escale

Alguém pergunta no chat. O sistema percorre um workflow multi-agente e responde com fontes — abrindo um chamado só depois de aprovação humana.

1 · Triagem

Classifica intenção e urgência antes de buscar qualquer coisa.

2 · Busca

Recuperação agêntica sobre a base, com a identidade de quem perguntou.

3 · Resposta

Fundamentada, com citação clicável. Sem fonte, declina.

4 · Escalonamento

Pausa e espera aprovação humana antes de agir.

Tudo avaliado (fundamentação + políticas) e rastreável (OpenTelemetry → Application Insights)

capacidades

Cada pilar do Foundry, validado na prática

  • ✓
    Base de conhecimento — recuperação agêntica sobre o corpus. Cita a fonte, ou declina quando a pergunta sai do que ele conhece.
  • ✓
    Workflow multi-agente — os passos chegam à tela enquanto acontecem, não depois.
  • ✓
    Memória + identidade delegada — memória por pessoa; a base é consultada como o usuário logado.
  • ✓
    Aprovação humana — escalar um chamado pausa até alguém autorizado aprovar. A ação não dispara antes disso.
  • ✓
    Avaliação — gate determinístico de políticas mais julgamento por modelo, ligados ao portal do Foundry.
  • ✓
    Deploy gerenciado — o mesmo workflow publicado como hosted agent.

O gerenciado é código num container, não um prompt. As respostas diferem um pouco de propósito — ele é uma variante simplificada, e modelos não são determinísticos.

modelos de entrega05 / 08

confiança

Avaliado e rastreável — não “confie em mim”

  • ▰
    Gate determinístico de políticas — toda resposta cita uma fonte (ou declina) e nunca vaza segredo. Viola, a entrega falha.um auto-teste planta a violação e prova que o gate a pega
  • ▰
    Julgamento por modelo — fundamentação, relevância e coerência sobre o conjunto de referência, com link para o relatório no portal.
  • ▰
    Rastreamento OpenTelemetry — cada interação vai para o Application Insights, com as notas ligadas aos rastros.

o que veio depois

Quatro domínios, um codebase, três modos de entrega

  • ▰
    Quatro domínios, não um — helpdesk (workflow), techdocs e selfwiki (fundamentados, com acesso por documento) e platform (ferramentas MCP com aprovação nas escritas).adicionar domínio = uma linha em cada registry + o agente
  • ▰
    Controle de acesso é dado, nunca lógica — cada documento é carimbado com quem pode lê-lo, e o corte acontece antes do modelo.medido com duas identidades reais: uma vê, a outra recebe zero
  • ▰
    Três modos de entrega — self-hosted, dedicated (Managed Application + Lighthouse) e shared (multi-tenant).o modo padrão continua byte-idêntico ao de antes
  • ▰
    Prompt não se edita em Python — cada agente é um documento publicável sem rebuild.
