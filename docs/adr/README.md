# Architecture Decision Records

ADRs capture significant architecture decisions: context → decision → consequences, each
grounded in the Microsoft guidance it follows. Format is lightweight (MADR-style).

## Index

| ADR | Decision |
|---|---|
| [ADR-001](./ADR-001-tenancy-deployment-stamps.md) | Tenancy model = **Deployment Stamps** (hybrid: shared + dedicated) |
| [ADR-002](./ADR-002-dedicated-stamp-managed-app-lighthouse.md) | Dedicated stamp = **Managed Application**; cross-tenant mgmt = **Azure Lighthouse** |
| [ADR-003](./ADR-003-multitenant-identity-obo.md) | Identity = **multi-tenant Entra app**, tenant from `tid`, **OBO** downstream |
| [ADR-004](./ADR-004-byo-data-plane-foundry-project.md) | Data plane = **BYO per-tenant**, Foundry **project** as the isolation boundary |
| [ADR-005](./ADR-005-never-store-secrets.md) | The control plane **never stores customer secrets** (passthrough + CMK refs) |
| [ADR-006](./ADR-006-tenant-scoped-config.md) | **Tenant-scoped** config — replace the global `settings`; namespace memory by tenant |
| [ADR-007](./ADR-007-coexistence-deployment-mode.md) | Coexistence via a **deployment-mode** seam (one codebase, three modes) |
| [ADR-008](./ADR-008-foundry-connections-app-configuration.md) | Use **Foundry connections + Azure App Configuration + Key Vault**, not a custom credential store |
| [ADR-009](./ADR-009-native-tool-approval-foundry-connection-resolution.md) | **Native tool-approval + Foundry-connection credential resolution** — no self-read Key Vault, no hand-rolled HITL |
| [ADR-010](./ADR-010-per-tenant-domain-entitlement.md) | Per-tenant domain enablement = **license entitlement** (stored on the tenant record), not a feature flag |
| [ADR-011](./ADR-011-hosted-per-tenant-foundry-toolbox-passthrough.md) | Hosted per-tenant tool resolution = **Foundry Toolbox + OAuth identity passthrough** (the agent never handles credentials) |
| [ADR-012](./ADR-012-reuse-upstream-deep-wiki-tooling.md) | Self-wiki generation = **reuse the upstream `microsoft/skills` deep-wiki plugin** (vendored at `.github/skills/`) + OpenWiki-style freshness regen; keep only our assurance layer (freshness half revisited by ADR-016) |
| [ADR-013](./ADR-013-declarative-agent-prompts-dna.md) | Agent instructions = **declarative data**, `prompts.py` becomes a composition shim guarded by a prompt-invariant eval suite in CI (the DNA scope it first used was replaced by ADR-015) |
| [ADR-014](./ADR-014-runtime-prompt-scope-no-rebuild.md) | Runtime agent definitions **decouple from the image** — local: compose bind-mount over the baked copy; prod (ACA): Azure Files share at `/mnt/agents` selected via `AGENTS_DIR`, baked copy as fallback (`scripts/push-prompts.sh`); prompt edits = **restart, not rebuild** |
| [ADR-015](./ADR-015-agentschema-replaces-the-dna-sdk.md) | Agent definitions become **Microsoft AgentSchema** (`apps/backend/agents/helpdesk/` [renamed to `agents/assured/` on 2026-08-24]) read by the official `agent-framework-declarative`; `dna-sdk` dropped. What the schema does not model — scope catalog, persona, guardrails, eval cases — stays repo-owned data with a small loader; `=Env.X` PowerFx indirection refused |
| [ADR-016](./ADR-016-openwiki-closes-the-freshness-loop.md) | *(Proposed)* Wiki **freshness** = consume **OpenWiki**'s diff → PR loop behind an adapter, replacing the `wiki-regen.yml` placeholder; generator and assurance layer unchanged. Contingent on a spike proving citations survive the `fidelity_min: 0.80` floor |
| [ADR-017](./ADR-017-module-boundaries.md) | *(Proposed)* The backend is organized by **business domain** — ten modules with `public`/`internal` over a shared kernel and one composition root — and the boundaries are **checked by CI** (`import-linter`). The measured import graph splits `auth.py` (shared kernel vs. tenant resolution) and moves `_domain_deps` to `tenancy` |
| [ADR-019](./ADR-019-langchain-hitl-comparison.md) | **Adopt LangChain's HITL for approvals** — The Agent Framework's approval is a **boolean**; LangChain's is a **conversation** (`approve`/`edit`/`reject`/`respond`, rejection with a reason, and a description factory that receives the agent state). Measured against both installed packages. `edit` is a stated product requirement and the Agent Framework offers only a boolean. Audit stays single because both sides speak **OTLP** and `shared/telemetry` already does. Costs a checkpointer and a second runtime; the role gate stays ours |
| [ADR-020](./ADR-020-canonical-frameworks-modular-organization.md) | **Use each framework the most canonical way possible; the modular monolith is the organization** — the frameworks' surfaces move faster than any abstraction over them could (agent-framework was preview; AHP breaks every MINOR; LangChain rewrote HITL three times), so a ports layer pays the churn twice. `shared` carries only what survives a runtime swap, decided by one written test. Supersedes 018 and 019 |
| [ADR-021](./ADR-021-canvas-flows-as-foundry-datasets.md) | **Canvas flows are stored as Foundry Datasets**, one version per save — `WorkflowAgentDefinition` looks like the home and is not: the service rejects Agent Framework YAML (`invalid_payload`), the field expects the portal's CSDL format, and **portal workflows retire 2026-12-01** with Microsoft directing users to the Agent Framework, where the definition lives with the application. Round-trip measured against the live project; disk drops to a boot-time fallback |
| [ADR-022](./ADR-022-proposer-not-publisher.md) | *(Proposed)* **The proposer drafts; Foundry optimizes; only a human publishes** — measured: the SDK's `OptimizationJob` already optimizes an EXISTING agent's instructions/model/skills/tools against evaluation scores and returns scored candidates whose `promotion` is null until someone promotes. The gap is proposing an agent that does NOT yet exist, from the tenant catalog, for a user with no portal. Publication is never the proposer's, and the boundary is checked by a gate rather than asserted. Path B rides the `.beta` namespace |
| [ADR-023](./ADR-023-evidence-layer.md) | *(Proposed)* **Azure owns immutability, we own the event** — this repo has a mature assurance layer and no evidence layer: it decides well and proves nothing. `approver_roles` is computed and discarded; the code cites an audit log five times that was never built; telemetry is off by default and deliberately omits the approver. Decision: a hash-chained append-only event stream on a **WORM container** (time-based retention + `allowProtectedAppendWrites`, SEC 17a-4(f)), **Confidential Ledger** as the swappable receipt upgrade, the HITL decision as the first event, and PII stopped at one structural write point |
| [ADR-018](./ADR-018-no-ahp-for-now.md) | **No `orchestration` ports and no AHP adoption now** — AHP is a client↔host protocol whose doctrine lists agent construction, credential flow and tool registry as anti-goals, and it is pre-1.0 with breakage expected. `registry.py`'s dispatch-by-`kind` is already the thin shell; the effort goes to per-tool approval/role policy as **data** in the AgentSchema documents. Explicit re-evaluation trigger |

| [ADR-024](./ADR-024-cost-truth-azure-first-focus-later.md) | *(Proposed)* **The price comes from Azure; FOCUS is the reconciliation, and it waits for volume** — the hand table's prices were right and its *matching* was wrong: longest-prefix matching made `gpt-5-pro` inherit `gpt-5`'s price (12× understated) and `gpt-4.1-nano` inherit `gpt-4.1`'s (20× overstated), neither ever reaching the "conservative fallback". `prices.azure.com` is public and unauthenticated, so no third-party price dataset is adopted — that would add a second accounting to diverge from the first. Unknown model yields `None`, never a plausible number. FOCUS is billing truth but not attribution (its `Tags` attach to resources, and one Foundry project serves four domains); the join key (`SkuMeter`) is stored now, the ingestion waits for a month of real spend |

| [ADR-025](./ADR-025-citation-transport-stays-ours-until-upstream.md) | *(Proposed)* **The citation vocabulary is the framework's; the transport stays ours until upstream closes the gap** — both frameworks already had a citation type (`agent_framework.Annotation`, `langchain_core.messages.Citation`) and we had invented `{index, source, url, content}` over them; that half is fixed. What remains is measured and reproducible: `_emit_text` reads only `content.text` while `_emit_usage`, four lines below, emits `CustomEvent(name="usage")` — same file, same dispatcher, one neighbour carried and the other dropped. Upstream #7460 is open, assigned, no PR. Customizing the adapter would mean monkeypatching a private module-level function of a volatile package; contributing upstream is the good route. Explicit re-evaluation trigger with a three-line reproduction |
| [ADR-026](./ADR-026-retrieval-stays-ours-mcptool-ignores-headers.md) | *(Proposed)* **A recuperação com ACL fica nossa — o `MCPTool` canônico ignora `headers`, medido** — um agente de teste com a KB anexada via `MCPTool` (o caminho canônico) devolveu os mesmos 38 documentos sem header, com o token do usuário e com um token inválido; o caminho próprio (`retrieval.py`, via `x-ms-query-source-authorization`) trimma corretamente (5 trechos com identidade, 0 sem, 401 com token inválido). O caminho canônico funciona bem no resto (planejamento, síntese, citações); só não aplica ACL por usuário, o que a RULE #6 exige. `retrieval.py` entra na mesma exceção da camada de assurance. Gatilho de reavaliação explícito se `headers` passar a ser honrado |

| [ADR-027](./ADR-027-mcp-app-separado-fastmcp-4.md) | **O MCP vira app separado para alcançar o FastMCP 4** — o `ServerExtension` que o T6 (selo de assurance como extensão de protocolo) precisa não existe no 3.4.7, e o 4 exige `mcp>=2` enquanto `agent-framework-core` trava em `<2` na versão mais nova publicada; o `mcp` 2.1.0 está estável, então o bloqueio é o teto de terceiro, não o SDK. Medido: `knowledge`, `audit`, `tenancy` e `shared` **já não importam** framework de agente — consequência não planejada da ADR-017. O obstáculo é o empacotamento, não o import: o framework vira extra do backend, e a limpeza do núcleo passa a ter contrato no `import-linter` **mais** um job que instala o base sem o extra e importa — o grafo prova o import, só a instalação prova a instalabilidade. Não há fronteira leitura/escrita: medir POR QUE `tickets`/`hitl` importavam dissolveu o maior custo previsto — era código morto (uma tool sem consumidor) e um adaptador reexportado pelo public, resolvidos com uma deleção e um import preguiçoso, com gate. Gatilho de reavaliação se o teto subir |
